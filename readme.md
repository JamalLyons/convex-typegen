# convex-typegen

Rust types from your [Convex](https://www.convex.dev) `schema.ts` and function modules. Runs in `build.rs` so generated code stays in sync with your backend.

**Docs:** [documentation website](https://jamallyons.github.io/convex-typegen/)

## Setup

1. Add the runtime as a normal dependency and the matching generator release as a build dependency.

```bash
cargo add convex-typegen-runtime
cargo add --build convex-typegen
```

2. Add `build.rs`:

```rust,ignore
use convex_typegen::prelude::*;

fn main() {
    if let Err(e) = convex_typegen::build::generate_out_dir() {
        panic!("convex-typegen failed: {e}");
    }
}
```

3. Include Cargo's generated file with `mod convex_api { convex_typegen_runtime::include!(); }`. Import runtime APIs from `convex_typegen_runtime`; the generator and runtime are separate crates with no re-exports. The default build helper tracks the schema and discovered/imported TypeScript sources. For a committed function spec, configure it explicitly. See the [tutorial](docs/guide/getting-started.md) and [macros](docs/macros.md).

A full minimal setup lives in [examples/basic](https://github.com/JamalLyons/convex-typegen/tree/master/examples/basic) in this repo.

## Generated models

Public endpoints generate typed references such as `api::admin::users::list` for
`admin/users:list`. Its declared argument and return models live in the same Rust
module, for example `api::admin::users::{ListArgs, ListReturn}`. Use the reference's
`path()` to get the canonical Convex identifier for the official SDK. Nested models
extend the enclosing type name. Struct fields use snake_case and Serde preserves
their exact wire spelling.

Import `convex_typegen_runtime::model::{Doc, Id, RawValue}` alongside the generated `tables`
module. A `Doc<tables::Tasks>` contains `_id: Id<tables::Tasks>` and `_creation_time: f64`.
Use `convex_typegen_runtime::value_serde::{to_value, from_value}` to convert models and SDK values.

See [generated models](docs/generated-models.md) for unions, field presence, and raw values.
Use the [typed client](docs/typed-client.md) to call generated references, subscribe to queries,
and decode application errors.

The [support matrix](docs/guide/support.md) lists parsed validators, discovery limits, skipped
functions, and raw fallbacks. See the [v0.4 migration guide](docs/guide/migration-v0.4.md) for the
breaking crate, generated-name, output-path, and client API changes.

## Defaults

| Field | Default |
| --- | --- |
| `schema_path` | `convex/schema.ts` |
| `out_file` | `$OUT_DIR/convex_api.rs` |
| `convex_dir` | `convex` |
| `function_spec_path` | `None` |

`Configuration::default()` selects `$OUT_DIR/convex_api.rs` when Cargo sets `OUT_DIR`. For a
standalone CLI invocation, pass `--output PATH`; this is also how to opt into committed output.
`convex-typegen --check --output PATH` compares the same generated bytes without writing and exits
with status 1 if the file is missing or drifted. Parser and validator errors include the source path
and byte range when available.

Paths are relative to the package directory when Cargo runs the build script.

Function sources: every `*.ts` under `convex_dir`, except the schema file, `_generated/`,
`node_modules/`, reserved modules (`http.ts`, `crons.ts`, `convex.config.ts`), and `*.d.ts`.
Relative imports of endpoint modules are included for Cargo invalidation. Set `function_paths` to a
non-empty list to skip directory discovery and pass files explicitly.

To use committed output from `npx convex function-spec` as the complete function inventory:

```rust,ignore
let config = Configuration {
    function_spec_path: Some("convex/function-spec.json".into()),
    ..Default::default()
};
```

The spec replaces TypeScript function discovery and parsing; the schema remains TypeScript. `rcfp`
returns the spec path so a build script can emit `cargo:rerun-if-changed` for it. Builds only read
the committed JSON and never run the Convex CLI or contact a backend. Refresh the v1 review capture
with `scripts/refresh-function-spec.sh` after deploying that fixture to the documented local backend.

## Runtime

`convex-typegen-runtime` uses the official `convex` client. Its
`value_serde::{to_value, from_value}` helpers convert directly against `convex::Value`.
Use `value_serde::Bytes` for byte strings. Generated optional fields omit outer `None`.
Select the nullable union's null branch to encode explicit `Null`.

Generated code imports Serde through the runtime. If your own code imports the
official client directly, declare `convex` in your dependencies too.

Keep `convex-typegen` in `[build-dependencies]` and `convex-typegen-runtime` in `[dependencies]`.
There are no v0.4 aliases or re-export shims; regenerate bindings and update imports using the
[migration guide](docs/guide/migration-v0.4.md).

## End-to-end verification

Run `just e2e` to deploy the fixture to a local self-hosted Convex backend in
Docker and exercise the generated client. See [the E2E guide](docs/e2e.md) for
prerequisites and coverage.

## Versioning

- [Semantic versioning policy](docs/semver-policy.md) — library API vs generated output, MSRV, and release rules.
- [API stability reference](docs/api-stability.md) — stable vs unstable public items.

Use the same release version of `convex-typegen-runtime` and `convex-typegen`. The runtime supports Rust **1.85**. Building from source with the generator requires Rust **1.95**, including when it runs from your build script. Projects that consume pregenerated bindings can depend on the runtime alone. When resolving a fresh lockfile on Rust 1.85, use Cargo resolver 3 to prefer compatible transitive dependencies. Edition 2024 uses it by default outside a workspace. On **0.x**, breaking codegen may ship in a **minor** (this crate, 0.4.0). From **1.0**, generated type renames require a **major** bump.

## Roadmap

v1 is a generated, fully typed function client: the Rust equivalent of Convex’s `api.*` (typed refs, args and return types, `Id<T>`, `Doc<T>`, subscriptions as streams). The picture, today’s gaps, and the open decisions are in [docs/v1-roadmap.md](docs/v1-roadmap.md).
